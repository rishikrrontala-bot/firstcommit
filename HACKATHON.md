## Submission requirements (from the event page)
- Working project created during the hackathon
- Public GitHub repository with source code
- Project description (what, how, problem solved)
- **Demo video, 3–5 minutes**
- README with setup instructions
- Recommended: live deployment, screenshots, technologies list, presentation slides

## Judging criteria

| Criterion | Weight |

- `docs/LEARNING.md`: an honest learning journal of the build (what was new, what broke, what changed and why), written as a draft for Rishik to personalise. Never invent experiences.
- `submission/deck.pdf` (recommended by the organizers)
- `submission/video/demo.mp4`: **3:00–5:00**

## Strategy notes (starting hypotheses, which the research may overturn)
- Learning & Growth is the heaviest weight, so the learning story must be real and specific.
- One polished, ambitious web experience can be in the running for Most Ambitious, Best Design, Best Web/App and Most Polished at once.

**Suggested lane:** Open: a delightful, ambitious web experience.
